## 2026-09-09 — Initial Loyverse sync: resumable, paginated, ordered (#7)

- `lib/loyverse/sync/engine.ts`: the §9 ordered sequence — validate credential → stores → categories → items(+variants) → employees → customers → receipts(+refunds) → stamp `lastSyncAt`. Runs inside the BullMQ worker only, never in an HTTP request. Org-scoped upserts keyed on the Loyverse id make re-processed pages idempotent; defensive field extractors let Loyverse schema drift degrade to null/0 instead of crashing mid-run
- Resumability (§9): after every page the engine persists `{done, cursors}` + cumulative counts on `SyncRun.progress` (migration `20260909002000_sync_run_progress`, one nullable JSONB column). A retried job skips `done` resources, resumes a partially-synced resource from its stored cursor, and merges counts per page — completed pages are never re-fetched or double-counted. Full runs (INITIAL/MANUAL) use checkpoints; INCREMENTAL runs always re-scan the delta with `updated_at_min`/`created_at_min` (receipts: `created_at_min`) since `lastSyncAt`
- `lib/loyverse/http.ts`: `LoyverseHttp.paginate` — cursor async-generator with in-request resilience: 429 honors `Retry-After` (capped, wins over base backoff), 5xx/network retry 5× exponential (2s→16s), 30s per-request timeout; 401/403 → `UnrecoverableError` (reconnect-required, dead-letters with a safe reason); exhaustion → `TransientJobError` so BullMQ retries and the run resumes from its checkpoint. A cursor passed in `params` seeds the first request (resume continues mid-resource instead of re-fetching the first page)
- Error taxonomy: invalid/revoked key, missing connection → `UnrecoverableError` (recorded on the run, job completes); Loyverse unreachable/rate-limited → `TransientJobError` (recorded AND rethrown → BullMQ backoff retry resumes); anything unexpected is recorded via `safeJobErrorMessage` (§19 redaction)
- Structural details: categories link parents in a second pass after all upserts (parent may sort after child); receipt lines pre-resolve local `variantId`s before nested create (lines are immutable from source); receipts whose store is unknown are skipped with a job log (store FK is required; employee/customer FKs optional); `parseLoyverseDate` normalizes Loyverse's `2024-01-15 10:30:45 +0000` to a strict ISO string

## 2026-09-09 — Auto-post receipts/refunds to the ledger (#11)

- `lib/finance/posting.ts` (SPEC.md §11 finance rules, §8 accounting invariants): on a completed receipt, builds a balanced journal entry from the org's GLMappings — debit the receipt `total` on the account mapped for the receipt's payment type; credit revenue per line (variant → item → category → category mapping), unmapped/uncategorized lines to the default revenue account code **4000**; a line-total/receipt-total mismatch is trued up on 4000 so the entry always balances. Refunds post the mirror entry (debit revenue, credit the parent receipt's payment account) — reversing revenue/receivable/cash impacts per mapping while the original receipt posting stays untouched (§11: never delete the original posting; refund entries do NOT use `reversalOfId`, which stays reserved for one-entry-fully-undoes-another manual reversals, #12)
- §8 invariants enforced in code: every posted entry has ≥1 debit and ≥1 credit; `assertBalanced` requires exact `Prisma.Decimal` equality of debit/credit sums (toFixed(2) into Decimal(14,2) columns — no float money anywhere); posting writes entry + lines + `LedgerSourceLink` + `journal.posted` audit row in ONE interactive `$transaction` (§18); posted lines are immutable by design (no update path)
